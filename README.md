# 学习空间 · Study Space

一个纯静态的个人知识库：把 Markdown 笔记按「知识模块」放进文件夹，打开浏览器就能阅读。没有服务端代码、没有构建步骤、不写任何文件。

- **一级入口**：首页列出全部知识模块
- **模块内阅读**：左侧目录（子文件夹即分类）、右侧本页目录、代码高亮、上一篇 / 下一篇
- 按名称（自然排序）或时间排序，子文件夹可多层嵌套、可折叠
- 标题与正文搜索、浅色 / 深色主题、手机适配
- 新增笔记或模块后刷新即可看到

## 启动与停止（Windows）

需要本机装有 Python 3。

| 操作 | 方式 |
| --- | --- |
| 启动 | 双击 `_reader/启动阅读器.bat`，会自动打开浏览器 |
| 停止 | 双击 `_reader/停止阅读器.bat`，或直接关掉那个最小化的服务窗口 |
| 改端口 | 编辑 `_reader/config.bat` 里的 `set PORT=47321` |

默认地址：<http://localhost:47321/_reader/>

其他系统可以在仓库根目录执行：

```bash
python3 -m http.server 47321 --bind 0.0.0.0
```

> 服务会把整个仓库目录以只读方式公开在这个端口上，不需要的话别对外网开放端口。

## 目录约定

```
学习空间/
├── fullstack/                     ← 一个知识模块（文件夹名会出现在网址里，建议用英文）
│   ├── _module.json               ← 可选：模块标题、简介、图标、排序
│   ├── 01-xxx.md                  ← 笔记；数字前缀决定阅读顺序，显示时会去掉
│   ├── 02-database/               ← 子文件夹 = 模块内的分类，可以多层嵌套
│   │   ├── _module.json           ← 可选：分类的标题、简介、图标、排序
│   │   ├── 01-mysql/
│   │   │   └── 01-index.md
│   │   └── 02-redis.md
│   └── 03-yyy.md                  ← 笔记和子文件夹按前缀混排：01 → 02 分类 → 03
├── another-topic/                 ← 以后学别的，就再建一个文件夹
└── _reader/                       ← 阅读器本身
```

- 笔记标题取自文件里第一个 `# 标题`，没有就用去掉数字前缀的文件名；front matter 里写了 `title` 时以它为准。
- 子文件夹在侧栏和模块页都显示为可折叠的分组；侧栏的折叠状态会记在浏览器里。
- 以 `.` 或 `_` 开头的文件和文件夹不会出现在阅读器里。
- 根目录下的 `.md`（比如本 README）不会被当作笔记。

### 排序

侧栏顶部和模块页都有排序开关，选择会记在浏览器里：

| 方式 | 规则 |
| --- | --- |
| 名称（默认） | 有数字前缀的排在前面，按数字大小（`9-` 在 `10-` 前面）；没有前缀的排在后面，按名称自然排序。文件夹的 `_module.json` 里写了 `order` 时以它为准 |
| 最新 / 最早 | 按笔记时间排序，文件夹按其中最新（或最早）的一篇参与排序 |

笔记时间：优先取 front matter 里的 `date`，没有就用文件的修改时间（静态服务器返回的 `Last-Modified`）。文件修改时间在换电脑、重新 clone 后会变，想让时间稳定就写 `date`：

```markdown
---
date: 2026-10-09
---

# 笔记标题
```

`上一篇 / 下一篇` 跟随当前的排序方式。

### `_module.json`

模块和子文件夹都可以放一个，字段都可选：

```json
{
  "title": "全栈工程师转型",
  "description": "一句话介绍",
  "icon": "🧱",
  "order": 1
}
```

## 发布到公网（阿里云 OSS 等静态托管）

本地阅读器靠 Python 静态服务器的「目录列表页」发现笔记。OSS、CDN、GitHub Pages 这类静态托管不提供目录列表，所以直接上传仓库是用不了的。为此加了一个构建步骤，把笔记清单提前生成好：

| 操作 | 方式 |
| --- | --- |
| 生成站点 | 双击 `_reader/构建静态站点.bat`，或在仓库根目录执行 `python _reader/build.py` |
| 输出位置 | 仓库根目录下的 `_dist/`（每次构建会先清空；已加入 `.gitignore`；`_` 开头，本地阅读器不会把它当成模块） |
| 换个输出目录 | `python _reader/build.py --out D:/site` |

`_dist/` 里的内容：

```
_dist/
├── index.html            ← 站点首页，自动跳转到 _reader/index.html
├── _reader/              ← 阅读器 + manifest.js（模块、分类、笔记、修改时间的清单）
└── fullstack/ ...        ← 各知识模块原样复制（图片等资源也一起带上）
```

- 阅读器发现页面里有清单就用清单，没有就照旧扫描目录列表，所以**本地双击启动的用法不受影响**。
- 所有路径都是相对的，上传到 Bucket 根目录或任意子目录都能用。
- **每次新增或修改笔记后要重新构建并上传**，线上才会更新。笔记的「修改时间」取构建时文件的修改时间（不是上传时间），写了 front matter `date` 的以 `date` 为准。

### 在 OSS 上托管

以下是需要注意的设置，具体菜单位置以阿里云控制台当前版本为准：

1. **上传**：把 `_dist/` 里的全部内容（不是 `_dist` 文件夹本身）上传到 Bucket，可以用控制台上传文件夹，或用 `ossutil` 命令行批量上传 / 同步。删掉的笔记要记得在 Bucket 里也删掉，同步命令一般有删除远端多余文件的选项。
2. **读写权限**：Bucket 设为「公共读」，或者保持私有、通过 CDN 回源访问。
3. **静态页面**：在 Bucket 的「静态页面」设置里，默认首页填 `index.html`。如果站点放在子目录里，打开「子目录首页」，否则访问 `https://域名/子目录/` 会 404，需要写全 `https://域名/子目录/index.html`。阅读器用 `#/` 路由，不需要配置 404 回退页。
4. **自定义域名**：用 OSS 默认域名直接打开 HTML 会被强制下载而不是显示，所以需要给 Bucket 绑定自己的域名（中国内地地域的域名需要备案），想要 HTTPS 再配置证书。
5. **缓存**：`manifest.js`、`app.js`、`app.css` 的链接带有构建时间作为版本号，重新部署后会自动拿新的；笔记 `.md` 每次都会重新请求。如果前面加了 CDN，记得给 `index.html` 设置不缓存或较短的缓存时间。

> 上传到公共读的 Bucket 后，所有笔记都是**公开**的，任何拿到链接的人都能看到。不想公开的内容放在 `_` 开头的文件夹里，它们会被阅读器隐藏，但**仍会被原样复制进 `_dist`**（以便图片等资源可用），如需完全不发布，请放到仓库外或在上传前删除。

同样的 `_dist/` 也可以直接放到 Nginx、GitHub Pages、Vercel 等任意静态服务器上。

## 技术说明

- `_reader/index.html` + `app.js` + `app.css`，依赖只有本地的 [marked](https://github.com/markedjs/marked) 和 [highlight.js](https://highlightjs.org/)（放在 `_reader/vendor`）。
- 本地模式：笔记列表来自静态服务器的目录列表页，任何会输出目录列表的静态服务器都能用。
- 构建模式：`_reader/build.py`（只用 Python 标准库）扫描仓库生成 `_dist/`，清单写在 `_reader/manifest.js`，由 `_dist` 里的 `index.html` 引入；阅读器检测到 `window.STUDY_SPACE_MANIFEST` 时不再请求目录列表。
